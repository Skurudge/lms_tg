# Курсовой проект: Бэкенд-платформа «Трекер атомных привычек»

## Описание проекта
Бэкенд-часть веб-приложения (SPA) для трекинга полезных привычек, спроектированная по мотивам бестселлера Джеймса Клира «Атомные привычки» [habits:models]. Сервер функционирует исключительно в режиме REST API, принимая и отдавая строго структурированные JSON-данные. Платформа построена на базе Django 6, Django Rest Framework (DRF) и СУБД PostgreSQL, а также оснащена асинхронным движком уведомлений Celery + Redis + Telegram API [config:settings].

## 📋 Чек-лист соответствия критериям оценки

### 1. Безопасность и CORS (Критерий оценки)
- [x] **Настройка CORS:** Внедрен пакет `django-cors-headers` [config:settings]. В `settings.py` прописана политика `CORS_ALLOW_ALL_ORIGINS = True` [config:settings]. Запросы от фронтенд-приложений проходят без CORS-ошибок.
- [x] **Изоляция данных (.env):** Все секретные ключи, логины, пароли СУБД и токен бота вынесены в изолированный файл `.env` [config:settings]. В корне проекта подготовлен демонстрационный файл-шаблон `.env.template` для наставника.

### 2. Модели и Бизнес-Валидаторы (Критерий оценки)
- [x] **Сущность привычки:** Модель `Habit` полностью описывает формулу Клира: пользователь (`owner`), место, время, действие, ролевые флаги приятности (`is_pleasant`) и публичности (`is_public`), вознаграждение, тайминг на выполнение и периодичность [habits:models].
- [x] **Комплексная валидация:** На уровне DRF-сериализатора подключены 5 кастомных валидаторов из `habits/validators.py` [habits:serializers]:
  1. *Запрет двух наград одновременно* (нельзя указать и текстовое вознаграждение, и связанную привычку).
  2. *Атомарное время* (время на выполнение жестко ограничено 120 секундами).
  3. *Фильтрация связей* (в связанные привычки могут попадать только приятные привычки с `is_pleasant=True`).
  4. *Запрет вложенности* (у приятной привычки не может быть своего вознаграждения или связанной привычки).
  5. *Регулярность* (нельзя выполнять привычку реже, чем один раз в 7 дней).

### 3. API Эндпоинты и Контроль Доступа (Критерий оценки)
- [x] **Авторизация по JWT:** Реализованы открытая регистрация пользователей с принудительным хэшированием паролей (`set_password`) и получение/обновление пары токенов через `djangorestframework-simplejwt` [users:urls].
- [x] **Защита личного CRUD:** Разработан кастомный класс `IsOwner` [habits:views]. Каждый пользователь имеет доступ исключительно к своим привычкам. В методе `perform_create` настроена автоматическая привязка сущности к текущему пользователю.
- [x] **Публичный API:** Выделен изолированный ReadOnly-эндпоинт `/api/habits/public/`, возвращающий список публичных привычек всех пользователей платформы без возможности их модификации [habits:urls].
- [x] **Пагинация DRF:** Настроен постраничный вывод списков строго по 5 элементов на страницу с корректной JSON-структурой ключей (`count`, `next`, `previous`, `results`) [habits:serializers].

### 4. Асинхронные Celery-задачи и Telegram (Критерий оценки)
- [x] **Интеграция с мессенджером:** Настроено асинхронное ядро Celery с переводом транспорта на протокол RESP2 для стабильной работы под ОС Windows без возникновения ошибок с командой `HELLO` [config:celery].
- [x] **Рассылка по расписанию:** Написана задача `send_habit_reminders` [habits:tasks], добавленная в ежеминутное расписание Celery Beat [config:celery]. Каждую минуту воркер сканирует базу данных, сопоставляет текущее московское время с таймингами привычек и отправляет напоминание пользователю.
- [x] **Обход блокировок и VPN:** Отправка сообщений реализована через прямые HTTP POST запросы к официальному шлюзу API Telegram, благодаря чему бот стабильно рассылает пуши из любой сетевой среды в РФ.

### 5. Качество кода и Тестирование (Критерий оценки)
- [x] **Соответствие PEP 8:** Все модули проекта оформлены в строгом соответствии с PEP 8, отформатированы через `black`, упорядочены `isort` и проверены линтером `flake8`. Прописана статическая типизация `mypy` [config:settings].
- [x] **Покрытие тестами 80%+:** В файле `habits/tests.py` написаны 10 комплексных автоматических тестов, полностью проверяющих CRUD, доступы и валидаторы [habits:tests]. Итоговый отчет покрытия зафиксирован в файле `coverage.txt` с показателем **85%**.

## Инструкция по развертыванию и запуску асинхронных служб

1. **Установите все зависимости проекта через Poetry:**
   ```bash
   poetry install
   ```
2. **Настройте файл переменных окружения `.env` в корне проекта:**
   Создайте файл `.env` на основе шаблона `.env.template` и заполните данные доступа к PostgreSQL, Redis и токен вашего Telegram-бота.
3. **Сгенерируйте и примените миграции базы данных:**
   ```bash
   poetry run python manage.py makemigrations
   poetry run python manage.py migrate
   ```
4. **Запустите службы в трех параллельных терминалах:**
   * **Терминал 1 (Сервер Django):** `poetry run python manage.py runserver`
   * **Терминал 2 (Воркер Celery):** `poetry run celery -A config.celery:app worker --loglevel=info -P solo`
   * **Терминал 3 (Планировщик Beat):** `poetry run celery -A config.celery:app beat --loglevel=info`
5. **Проверка документации:**
   * Интерактивный Swagger UI доступен по адресу: http : // localhost : 8000 / api / docs / swagger /
   * Альтернативная документация Redoc доступна по адресу: http : // localhost : 8000 / api / docs / redoc /
